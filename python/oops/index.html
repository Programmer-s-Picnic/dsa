1. What are magic methods?

In Python Object-Oriented Programming, magic methods are special methods whose names start and end with double underscores. They are also called dunder methods.

Python 
__init__
__str__
__repr__
__len__
__add__
__getitem__
__iter__
__next__

We usually do not call these methods directly. Python calls them automatically when we perform normal actions.

Normal action Magic method Python calls
print(obj) obj.__str__()
len(obj) obj.__len__()
obj1 + obj2 obj1.__add__(obj2)
obj[index] obj.__getitem__(index)
for value in obj obj.__iter__() and obj.__next__()
Simple idea: Magic methods teach Python how your own objects should behave when used with ordinary Python syntax.

2. __init__: the object setup method

The __init__ method runs automatically when a new object is created. It is used to store the first values inside an object.

Python 
class Student:
    def __init__(self, name, marks):
        self.name = name
        self.marks = marks


s1 = Student("Amit", 85)

print(s1.name)
print(s1.marks)

Output:

Output 
Amit
85
Checkpoint: When we write Student("Amit", 85), Python automatically calls __init__.

Common beginner confusion

__init__ is not the object itself. It is the method that prepares the object after it is created.

3. __str__ and __repr__: showing objects properly

Without __str__

Python 
class Student:
    def __init__(self, name, marks):
        self.name = name
        self.marks = marks


s1 = Student("Amit", 85)
print(s1)

Output may look like this:

Output 
<__main__.Student object at 0x000001A2...>

This output is not useful for a student or a normal user.

With __str__

Python 
class Student:
    def __init__(self, name, marks):
        self.name = name
        self.marks = marks

    def __str__(self):
        return f"{self.name} scored {self.marks} marks"


s1 = Student("Amit", 85)
print(s1)

Output:

Output 
Amit scored 85 marks

Using __repr__

__repr__ is generally used for programmer-friendly output.

Python 
class Student:
    def __init__(self, name, marks):
        self.name = name
        self.marks = marks

    def __repr__(self):
        return f"Student(name='{self.name}', marks={self.marks})"


s1 = Student("Amit", 85)
print(repr(s1))

Output:

Output 
Student(name='Amit', marks=85)
Method Purpose
__str__ Friendly output for users
__repr__ Clear output for programmers and debugging

4. Operator overloading with magic methods

Operator overloading means giving special meaning to operators such as +, -, *, and > for our own classes.

Problem first

Python 
class Money:
    def __init__(self, amount):
        self.amount = amount


m1 = Money(100)
m2 = Money(200)

print(m1 + m2)

Python does not automatically know how to add two Money objects. So we define __add__.

Solution with __add__

Python 
class Money:
    def __init__(self, amount):
        self.amount = amount

    def __add__(self, other):
        return Money(self.amount + other.amount)

    def __str__(self):
        return f"₹{self.amount}"


m1 = Money(100)
m2 = Money(250)

m3 = m1 + m2

print(m3)

Output:

Output 
₹350
Checkpoint: When we write m1 + m2, Python internally calls m1.__add__(m2).

Common operator magic methods

Operator Magic method
+__add__
-__sub__
*__mul__
/__truediv__
//__floordiv__
%__mod__
**__pow__

Example with boxes

Python 
class Box:
    def __init__(self, chocolates):
        self.chocolates = chocolates

    def __add__(self, other):
        return Box(self.chocolates + other.chocolates)

    def __sub__(self, other):
        return Box(self.chocolates - other.chocolates)

    def __str__(self):
        return f"Box has {self.chocolates} chocolates"


b1 = Box(20)
b2 = Box(5)

print(b1 + b2)
print(b1 - b2)

Output:

Output 
Box has 25 chocolates
Box has 15 chocolates

5. Comparison magic methods

Comparison magic methods allow us to compare two objects using normal comparison operators.

Comparison Magic method
==__eq__
!=__ne__
>__gt__
<__lt__
>=__ge__
<=__le__

Student marks comparison

Python 
class Student:
    def __init__(self, name, marks):
        self.name = name
        self.marks = marks

    def __gt__(self, other):
        return self.marks > other.marks

    def __eq__(self, other):
        return self.marks == other.marks


s1 = Student("Amit", 85)
s2 = Student("Ravi", 90)
s3 = Student("Sita", 85)

print(s1 > s2)
print(s1 == s3)

Output:

Output 
False
True
We compared students by marks, but we could also compare them by age, rank, fees, attendance, or any other data.

6. Making objects behave like containers

Python lists, tuples, dictionaries, and strings support operations such as len(), indexing, assignment by index, and in. Magic methods allow our own objects to support these actions too.

__len__: support for len()

Python 
class Classroom:
    def __init__(self, students):
        self.students = students

    def __len__(self):
        return len(self.students)


c1 = Classroom(["Amit", "Ravi", "Sita"])

print(len(c1))

Output:

Output 
3

__getitem__: support for indexing

Python 
class Marksheet:
    def __init__(self, marks):
        self.marks = marks

    def __getitem__(self, index):
        return self.marks[index]


m = Marksheet([80, 75, 90, 88])

print(m[0])
print(m[2])

Output:

Output 
80
90

__setitem__: support for changing values by index

Python 
class Marksheet:
    def __init__(self, marks):
        self.marks = marks

    def __getitem__(self, index):
        return self.marks[index]

    def __setitem__(self, index, value):
        self.marks[index] = value


m = Marksheet([80, 75, 90])

print(m[1])
m[1] = 95
print(m[1])

Output:

Output 
75
95

__contains__: support for in

Python 
class Classroom:
    def __init__(self, students):
        self.students = students

    def __contains__(self, name):
        return name in self.students


c = Classroom(["Amit", "Ravi", "Sita"])

print("Amit" in c)
print("Mohan" in c)

Output:

Output 
True
False

7. Iterators with __iter__ and __next__

An iterator is an object that gives values one by one. When we use a for loop, Python internally uses iteration.

Simple idea: If your object has __iter__ and __next__, Python can take values from it one at a time.

How a normal list is used in a loop

Python 
numbers = [10, 20, 30]

for num in numbers:
    print(num)

Output:

Output 
10
20
30

Lists already know how to give values one by one. Now let us make our own class work like this.

Creating our own iterator

Python 
class CountUpTo:
    def __init__(self, limit):
        self.limit = limit
        self.current = 1

    def __iter__(self):
        return self

    def __next__(self):
        if self.current <= self.limit:
            value = self.current
            self.current += 1
            return value

        raise StopIteration


counter = CountUpTo(5)

for number in counter:
    print(number)

Output:

Output 
1
2
3
4
5
Method Meaning
__iter__ Returns the iterator object. In many simple iterators, it returns self.
__next__ Returns the next value. When values are finished, it raises StopIteration.
StopIteration A signal that tells Python the iteration is complete.

What Python does internally

This for loop:

Python 
for number in counter:
    print(number)

behaves somewhat like this:

Python 
iterator = iter(counter)

while True:
    try:
        number = next(iterator)
        print(number)
    except StopIteration:
        break
Checkpoint: iter(counter) calls counter.__iter__(), and next(iterator) calls iterator.__next__().

Iterator example with students

Here we create a classroom object that can be used directly in a for loop.

Python 
class Classroom:
    def __init__(self, students):
        self.students = students
        self.index = 0

    def __iter__(self):
        self.index = 0
        return self

    def __next__(self):
        if self.index < len(self.students):
            student = self.students[self.index]
            self.index += 1
            return student

        raise StopIteration


c = Classroom(["Amit", "Ravi", "Sita"])

for student in c:
    print(student)

Output:

Output 
Amit
Ravi
Sita
Important: Always raise StopIteration when no values are left. If you forget this, your iterator may run forever.

Simpler way: using yield

In real Python projects, we often use yield to create iterators more simply. This creates a generator.

Python 
class Classroom:
    def __init__(self, students):
        self.students = students

    def __iter__(self):
        for student in self.students:
            yield student


c = Classroom(["Amit", "Ravi", "Sita"])

for student in c:
    print(student)

Output:

Output 
Amit
Ravi
Sita
Teacher's tip: Learn __iter__ and __next__ to understand the mechanism. Use yield when you want a cleaner real-world solution.

8. Advanced but useful magic methods

__call__

This method makes an object behave like a function.

Python 
class Greeter:
    def __call__(self, name):
        return f"Hello, {name}!"


g = Greeter()

print(g("Amit"))
print(g("Sita"))

Output:

Output 
Hello, Amit!
Hello, Sita!

__bool__

This method controls truth testing with if object:.

Python 
class Wallet:
    def __init__(self, money):
        self.money = money

    def __bool__(self):
        return self.money > 0


w1 = Wallet(500)
w2 = Wallet(0)

print(bool(w1))
print(bool(w2))

Output:

Output 
True
False

__del__: object destruction

The method __del__ may run when an object is about to be destroyed. However, in real projects we should not depend on its exact timing.

Python 
class Demo:
    def __init__(self):
        print("Object created")

    def __del__(self):
        print("Object destroyed")


d = Demo()
del d
Important: Do not use __del__ as your main cleanup plan in serious programs. Python controls memory automatically, and destruction time may not always be exactly when you expect.

9. Mini project: Shopping Cart with magic methods

This project shows how magic methods make our own class feel natural, like a normal Python container. It supports print(cart), len(cart), "Mouse" in cart, cart[0], and for item in cart.

Python 
class ShoppingCart:
    def __init__(self):
        self.items = []

    def add_item(self, item):
        self.items.append(item)

    def __len__(self):
        return len(self.items)

    def __contains__(self, item):
        return item in self.items

    def __getitem__(self, index):
        return self.items[index]

    def __iter__(self):
        return iter(self.items)

    def __str__(self):
        return f"Cart contains: {self.items}"


cart = ShoppingCart()

cart.add_item("Laptop")
cart.add_item("Mouse")
cart.add_item("Keyboard")

print(cart)
print(len(cart))
print("Mouse" in cart)
print(cart[0])

for item in cart:
    print("Item:", item)

Output:

Output 
Cart contains: ['Laptop', 'Mouse', 'Keyboard']
3
True
Laptop
Item: Laptop
Item: Mouse
Item: Keyboard
Checkpoint: This object supports print(cart), len(cart), "Mouse" in cart, cart[0], and for item in cart.

11. Common mistakes beginners make

1. Calling magic methods directly

Beginners sometimes write obj.__str__() directly. It works, but it is not the normal style. Use str(obj) or print(obj) instead.

Python 
# Not preferred
print(obj.__str__())

# Better
print(obj)

2. Forgetting to return a value

Methods like __str__, __len__, and __add__ must return something useful.

Wrong 
class Student:
    def __str__(self):
        print("Student object")

Correct version:

Correct 
class Student:
    def __str__(self):
        return "Student object"

3. Returning a non-string from __str__

The __str__ method must return a string.

Wrong 
class Student:
    def __str__(self):
        return 100

Correct version:

Correct 
class Student:
    def __str__(self):
        return "100"

4. Not checking the other object

In methods like __add__ and __gt__, make sure the other object has the expected data.

Python 
class Money:
    def __init__(self, amount):
        self.amount = amount

    def __add__(self, other):
        if not isinstance(other, Money):
            return NotImplemented

        return Money(self.amount + other.amount)

5. Forgetting StopIteration in iterators

If __next__ never raises StopIteration, Python will not know when the loop should stop.

Wrong 
class BadCounter:
    def __next__(self):
        return 1   # This can keep going forever

Correct idea:

Correct 
def __next__(self):
    if finished:
        raise StopIteration

    return next_value
Teacher's tip: Magic methods are powerful, but they should make the object easier to use, not harder to understand.
