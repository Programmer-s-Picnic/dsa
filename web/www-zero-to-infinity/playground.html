Lab 2 — Compare localStorage and sessionStorage

Write a harmless nickname. Save it in each browser storage system. Reload, open another tab, and close/reopen to investigate persistence.

No demo storage action yet.

These are browser-side, origin-scoped key/value stores. Neither sends stored values automatically with every HTTP request. sessionStorage is tied to a tab's page session; duplicated/opened tabs can initially receive a copy depending on how created.

Lab 6 — Understand a real server-side session

This is a diagram, not a working login. In a real app, the server validates credentials, generates a safe session ID, stores or cryptographically validates session information, sets a protected cookie, and checks the session on protected requests.
