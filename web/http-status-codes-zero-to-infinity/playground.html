How to use this page

Press F12 (or Ctrl + Shift + I) in desktop Chrome → open Network → click Fetch/XHR. Keep the recording button enabled. Trigger each example below, and then inspect the request's Headers, Preview, Response, Initiator and Timing tabs.

Part B — More real HTTP responses (run local server)

To use these controls, save status-server.js, playground.html and sample-ok.json in one directory, install Express and run the local server. You can also clone the DSA repository.

npm init -y
npm install express
node status-server.js
# Open http://127.0.0.1:3000/ in Chrome.

The 2xx, 4xx and 5xx buttons return real numeric HTTP responses but simulated scenarios. The endpoint reporting “502” is not actually contacting an upstream server; it teaches the meaning of that status and where it would appear.

Part C — Redirects: find the hidden 3xx response

A browser usually follows redirects automatically. Therefore the JavaScript fetch() call may show a final 200 even though DevTools records a preceding 302, 303, 307 or 308. Turn on Preserve log before testing.

Local Node.js server required for redirect experiments.

Part D — Cache validators and 304 Not Modified

The local server provides /api/cache-demo with the header ETag: "champuter-lesson-v1" and Cache-Control: no-cache. Make a normal request, then send the same ETag in If-None-Match. The latter can produce 304. Chrome may combine cached content with the 304 response, so also verify with the command shown below.

304 means cached content can be reused; it does not mean the resource was deleted.
curl -i http://127.0.0.1:3000/api/cache-demo
curl -i -H 'If-None-Match: "champuter-lesson-v1"' \
  http://127.0.0.1:3000/api/cache-demo

Part E — Your Chrome DevTools investigation checklist

  1. Click a request and find Request URL, Request Method and Status Code.
  2. Look for Location on a redirect and WWW-Authenticate on the 401 demo.
  3. Find Allow on 405 and Retry-After on 429 or 503.
  4. Examine 204: there is no response body.
  5. Examine 206: find the Content-Range header.
  6. Use Network filter status-code:404 or status-code:500 to isolate errors.
  7. Check Initiator to find the code that sent the request.
  8. Use the Timing tab to inspect waiting/transfer time.
  9. Switch the network to Offline and compare a genuine network failure with an HTTP 404 response; restore normal connectivity.
